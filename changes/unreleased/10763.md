### Added

- **`omo doctor --models` shows which model every task category and agent runs, and `exclude_models` keeps a model out of all of them.** The new doctor view prints, per category and agent, the model a spawn runs first, the retry chain in order, and each rung's source (built-in, omo.json, or the category an agent borrows) with why it does or does not run: excluded, no login, or not reached. It reads the same resolvers spawns use, and `--json` gives the same view to scripts. The new top-level `exclude_models` list (`provider/model`, a bare model id, or a `*` pattern such as `"claude-fable-*"`) is honored by category and agent chains, memory children (the session model they would inherit included), the main session's model profile, explicit task pins, and task children respawned or resumed on a recorded model, including their recorded fallback chains. Before, no setting could stop a builtin rung from running; only logging out of its provider did (#10759, #10763).
